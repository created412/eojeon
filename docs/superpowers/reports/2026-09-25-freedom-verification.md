## 실제로 확인한 경로

- **보고 먼저 / 사람 먼저:** 실제 `main.js`의 `runBeats()` 본문을 실행해 1~5막을 완주한다. 방문·읽은 사료·미방문 기록은 다르고, 필수 사건과 아홉 번의 궁 이동 순서는 같다.
- **기존 비트 정순 / 역순:** 4막의 `wanhwa-death`와 `jaeseon-order`를 반대 순서로 읽는 두 경로도 5막까지 완주한다. 현재는 1882년이라는 회고 표시, 각 기록의 원래 연도·원문·등급·근거를 보존한다. 열람 순서가 사건 발생 순서를 바꾸지 않는다.
- **모든 선택 생략:** 9개 거점을 활동 없이 나가도 5막 엔딩까지 간다. 보지 않은 선택 보고의 사료를 지급하지 않으며, 하지 않은 활동을 사실로 남긴다.
- **새 저장 경계:** 두 방문 정책의 자동 검사에서 만든 모든 저장 지점을 직렬화하고 재개해 같은 최종 기록에 도달한다. 보고 비용 지불 직후의 재개는 다시 비용을 내지 않는다.
- **구형 버전 3 저장:** 이미 지난 보고를 반복하지 않는다. 재생 중인 보고뿐 아니라 보고 시작 직전 저장도 원래 위치에서 이어 보고, 새 거점에서 중복 제공하지 않는다.
- **공간 이동:** 거점별 열린 선택지 22건을 실제 조작권으로 `objectiveRoute()`와 `movement.step()`을 사용해 걸어간다. 도착 위치와 방을 검사한다.
- **화면:** 390×844와 1024×768 브라우저에서 선택·닫기·생략·엔딩을 확인하고, 버튼 너비와 최소 높이 48px를 검사한다. 마지막 사료·대화·선택 목록이 열린 동안 다음 사건이 덮지 않는다.

별도 HTML 실행 검사는 저장된 3막에서 여정 판을 열고 사정전으로 실제 렌더 루프를 따라 걸어간다. 최익현 상소의 비용 지불 직후 새로고침해 보고를 다시 보고, 해 칸이 이중 차감되지 않는 것을 확인한다. 구형 저장이 같은 보고 시작 직전에 있는 경우도 실제 화면에서 확인한다.

## 검증 중 보완한 것

- 기존 보고끼리도 순서를 바꿀 수 있는지 검사하기 위해 4막의 지난 기록 두 개를 회고 선택지로 묶었다. 최종 선택 보고·기록은 6개다. 역사 전환 효과가 있는 비트는 선택 활동으로 옮기지 않는다.
- 구형 저장이 이미 거점을 지나 선택 보고 직전에 있는 경우, 그 보고를 단순히 생략하지 않고 원래 자리에서 마치게 했다.
- 자유 걷기로 방향을 바꾸면 기존 방문 목표가 다른 대화를 막지 않도록 취소한다.
- 새 브라우저 시험은 전체 병렬 실행에서 기본 5초 제한을 넘을 수 있어 해당 시험에만 30초 한도를 지정했다. 게임의 촉박 제한 시간은 변경하지 않았다.

## 보존 범위와 검증의 한계

기존 90개 비트의 ID와 배열 순서를 보존했다. 1875~1876 탐색의 협상 준비 시점을 1876년으로 명시한 메타데이터만 보충했다. 저장 키 `eojeon.save.v1`, 버전 3, 조작권, 사료 등급·근거, 기록형 엔딩은 유지한다. 새 이미지·음원·모델이나 의존성은 추가하지 않았다.

1~5막 검사는 화면 대기와 학생 입력을 자동 정책으로 대체한 시나리오 실행이다. 실제 HTML 브라우저 검사는 한 거점의 화면·이동·저장 연결을 확인한다. 실물 태블릿의 프레임률, 장시간 사용감, 학생이 느끼는 재미와 수업 시간 배분까지 검증한 것은 아니다. `game-dev` CLI는 사용하지 않았다.
