## 1. 왜 다시 만드는가 — 기존 게임 진단

### 1.1 기존 게임의 구조

*This War of Mine* 형 은신처 생존 시뮬레이션. 단일 HTML(3.7MB, base64 내장).

| 층위 | 내용 |
|---|---|
| 시나리오 | 사라예보 포위(1992–96), 레닌그라드 포위(1941–44) 2종 |
| 무대 | 4×3 방 격자 단면도(작업실·주방·침실·의무실·현관·지하 등 12칸) |
| 캐릭터 | 생존자 3명, 특성 4종, 스탯 5종(허기·피로·체력·정신·동상) |
| 낮 | 생존자 클릭 → 방 클릭 → 제작/요리/수면/치료/식사, 난로 가동 |
| 밤 | 1명 탐색 파견(5개 장소, 위험도 1~3, 배낭 15칸) + 잔류 인원 경계 |
| 자원 | 12종 (목재·부품·기계부품·음식·물·약·붕대·허브·연료·귀중품·무기·식재료) |
| 진행 | 랜덤 이벤트 1개/일 → 선택 → 역사 메모 팝업 |
| 종료 | 랜덤 16~24일 생존 시 "정전", 전멸 시 종료 |

### 1.2 진단 — 일곱 가지 문제

**① 제목과 내용의 불일치.**
파일명은 '스탈린그라드'이나 실제 시나리오는 사라예보·레닌그라드다. 부제 '전쟁과 과거사'의 '과거사'에 대응하는 게임 요소가 하나도 없다.

**② 역사 학습이 스킵 가능한 부가물이다. (최대 문제)**
역사 메모는 선택 *이후* 모달로 뜨고, 읽지 않아도 게임 진행에 아무 영향이 없다. 학생은 확인 버튼만 누른다. 교육 내용이 게임 메커닉의 **바깥에** 붙어 있다.

**③ 선택의 결과가 역사가 아니라 숫자로 돌아온다.**
"이웃 아이에게 음식을 나눠준다" → `food-1, mood+8`. 도덕적 딜레마를 던지고 피드백은 사기 게이지다. 왜 그 상황이 벌어졌는지(봉쇄·배급제·암시장·국제개입 지연)라는 구조적 인과가 규칙에 없다.

**④ 무작위 이벤트라 역사적 시간성이 없다.**
`evs[rnd(0, evs.length-1)]` — 1일차에 '125g 배급'이 뜰 수 있다. 포위전의 단계(초기 낙관 → 첫 겨울 기근 → 대량 아사 → 협상)를 학생이 경험하지 못한다.

**⑤ 랜덤 종료일(16~24일)이 학습을 방해한다.**
플레이어가 계획을 세울 수 없어 좌절만 남고, 실제 1,425일이라는 압도적 장기성과의 대비도 사라진다.

**⑥ 성찰과 산출물이 없다.**
엔딩은 읽고 끝. 학생이 자기 선택을 되돌아볼 기록도, 교사가 수업·평가에 쓸 선택 로그도 나오지 않는다.

**⑦ 게임으로서도 얕다.**
자원 12종을 두고도 의사결정은 대부분 '부족한 걸 채운다' 한 방향이다. 날카로운 트레이드오프가 이벤트에만 있고 시스템에는 없다.

### 1.3 재설계의 한 문장

> **역사를 게임의 통화(currency)로 만든다.**
> 사료를 읽어야 더 나은 수가 열리고, 1막의 모든 선택은 2막에서 증언·증거·기억이 되어 돌아온다.

## 3. 1막 — 포위 (14분 / 게임 내 12일)

### 3.1 3국면 고정 구조

무작위 이벤트 추출을 폐기하고, 국면별 이벤트 풀에서 **순서대로** 뽑는다. 각 국면은 기온·위협·이벤트 성격이 다르다.

#### 국면 1 · 1~4일 「봄, 아직은 견딜 만하다」 (1992년 4~5월)

- 기온 +12 ~ +18°C. 난방 불필요. 전기·수도가 간헐적으로 들어온다.
- 자원은 아직 여유. 학생은 조작을 익히고 방심한다.
- 이벤트: 상점 사재기 / 첫 저격 / 이웃과의 첫 나눔 / 떠난 사람들

#### 국면 2 · 5~8일 「겨울, 도시가 얼어붙다」 (1992년 12월~)

- 기온 -5 ~ -15°C. 난방 필수, 연료가 급속히 마른다.
- 전기·수도 완전 차단. 물은 공동 급수대에서만.
- 이벤트: 공원 벌목 / 책과 가구 태우기 / 마르칼레 시장 포격 / UN 호송대 지연

#### 국면 3 · 9~12일 「끝이 보이지 않는다」 (1993~)

- 기온 -10 ~ 0°C. 자원 고갈, 밤 침입 빈도 최대.
- 이벤트: 희망의 터널 / 암시장 / 떠날 것인가 남을 것인가 / **기록할 것인가**

> **국면 3의 '기록할 것인가'는 특수 이벤트다.** 일기를 쓸지, 사진을 찍을지, 이웃의 이름을 적어둘지 선택한다. 이 선택이 2막 문 ①에서 **물증 카드**의 유무를 결정한다. 게임 안에서 "사료는 누군가 남겨서 존재한다"는 사실을 경험시키는 장치다.

### 3.2 사료를 선택 '앞'으로 — 핵심 메커닉

**기존:** `이벤트 → 선택 → 결과 → 역사 메모 팝업(스킵됨)`
**신규:** `이벤트 + 📄자료 → (자료 읽으면 선택지 해금) → 선택 → 결과`

```
┌─────────────────────────────────────────────────┐
│ 사건 — 배급소 앞                          6일차 │
├─────────────────────────────────────────────────┤
│ 빵 배급이 줄었다는 소문이 돈다.                 │
│ 세 시간 줄을 설 것인가?                         │
│                                                 │
│  📄 자료 보기          [읽으면 선택지가 열립니다]│
│   └ UNHCR 1993 배급 기록 — 사라예보 시민        │
│     1인당 하루 평균 159g. 호송대가 막히면        │
│     그마저 끊겼고, 호송은 주 단위로 지연됐다.    │
│     [해금] "오늘은 호송대 도착 예정일이다"       │
│                                                 │
│  ○ 세 시간 줄을 선다                            │
│  ○ 포기하고 돌아온다                            │
│  ● 오후에 다시 온다        ← 자료를 읽어야 보임 │
└─────────────────────────────────────────────────┘
```

**설계 원칙**

- 해금 선택지는 **더 유리하되 무료는 아니다.** 위 예시의 '오후에 다시 온다'는 식량을 더 얻지만 하루 행동 1회를 소모한다. 사료 읽기가 정답 버튼이 되면 안 된다.
- 자료는 **3~4줄**을 넘지 않는다. 20분 안에 12개 이벤트를 소화해야 한다.
- 전체 12개 이벤트 중 **6~7개**에만 해금 선택지를 붙인다. 매번 있으면 패턴이 되어 읽지 않고 클릭한다.
- 자료를 읽었는지 여부를 `readSources[]`에 기록한다 → 엔딩 카드에 "당신은 12개 자료 중 N개를 읽었다"로 표시.

### 3.3 숨은 4태그

모든 이벤트 선택과 일부 낮 행동에 태그를 적립한다.

| 태그 | 의미 | 적립 예시 |
|---|---|---|
| `연대` | 이웃·타인을 도왔는가 | 굶주린 아이에게 빵을 나눔, 부상당한 이웃을 붕대로 치료 |
| `기록` | 남겼는가 | 일기 쓰기, 사진 찍기, 이웃의 이름 적기, 자료 읽기 |
| `생존` | 가족을 지켰는가 | 무사히 생존, 방어 시설 건설, 식량 비축 |
| `침묵` | 외면했는가 | 이웃을 두고 피신, 나눔 거절, 자료를 읽지 않음 |

**HUD에 절대 표시하지 않는다.** 게이지로 보이는 순간 학생은 점수 따먹기를 하고, 도덕적 선택이 최적화 문제로 변질된다. 2막에서 처음 공개된다.

`생존`과 `침묵`은 대립하지 않는다 — 둘 다 높을 수 있다. 이것이 이 게임의 도덕적 핵심이다.

### 3.4 시스템 압축

20분 제약을 맞추고 트레이드오프를 날카롭게 하기 위한 정리.

| 항목 | 기존 | 신규 | 비고 |
|---|---|---|---|
| 자원 | 12종 | **6종** | 음식 · 물 · 연료 · 의약 · 부품 · 귀중품 |
| 방 | 12칸 (4×3) | **6칸 (3×2)** | 주방 · 침실 · 작업실 · 의무실 · 현관 · 지하 |
| 제작 트리 | 작업대 3단계 | **2단계** | 침대 / 난로 / 빗물받이 / 바리케이드 / 붕대 / 약 |
| 탐색지 | 5곳 | **3곳** | 시장(위험2) · 급수대(위험2) · 공원(위험1) — 국면 3에 터널(위험3) 추가 |
| 배낭 | 15칸 | **6칸** | 무엇을 버릴지 강제 → 선택이 날카로워짐 |
| 생존자 | 3명 | 3명 유지 | 에미르(손재주) · 야스나(요리) · 다보르(체력) |
| 스탯 | 5종 | 4종 | 허기 · 피로 · 체력 · 정신 (동상은 체력에 통합) |

### 3.5 1막 종료 연출

12일차 종료 시 정전이 아니라 **숫자 연출**로 끝낸다.

```
        당신은  12 일을 버텼습니다.

        사라예보 시민들은

            1  2  3 ...  1,425
                          일을 버텼습니다.

     (1992.4.5 – 1996.2.29 · 현대사 최장기 수도 포위)
```

카운트업 애니메이션 3초. 기존의 '랜덤 16~24일 정전'보다 교육적 타격이 비교할 수 없이 크다. 여기서 학생은 자신이 겪은 12일이 실제의 **0.8%**였음을 알게 된다.

## 4. 2막 — 세 개의 문 (7분)

### 4.0 막간 (1분)

> **2002년.**
> 포위가 끝난 지 6년이 지났다.
> 당신은 살아남았다.
> 그리고 이제, 질문을 받는다.

화면이 은신처 단면도에서 빠져나와 밝은 실내로 전환된다. HUD(자원·날짜)가 사라지고 대신 손에 쥔 **기억 카드**가 나타난다.

### 4.1 문 ① 증언 — 무엇을 말할 것인가 (2분)

헤이그 ICTY 조사관이 진술을 요청한다. 1막 `choiceLog[]`에서 **자동 생성된 기억 카드 6장**이 손에 쥐어지고, **3장만 제출할 수 있다.**

```
「4일차 · 급수대에서 저격당한 이웃을 두고 돌아왔다」
「6일차 · 배급소 앞에서 세 시간을 줄 섰다」
「7일차 · 야스나가 책을 태워 밤을 났다」
「9일차 · 옆집 아이에게 마지막 빵을 나눠주었다」
「10일차 · 터널에 가지 않았다」
「11일차 · 이웃의 이름을 수첩에 적었다」
```

**태그 연동**

- `기록` 높음 → **물증 카드**(사진·일기·수첩)가 추가로 들어온다. 물증이 붙은 증언은 신뢰도가 크게 오른다.
- `기록` 낮음 → 물증 없음. 조사관이 "확인할 방법이 없군요"라고 답한다.
- `침묵` 높음 → 카드 일부가 흐릿하게 표시된다("기억이 확실하지 않다"). 제출은 되지만 신뢰도가 낮다.
- 부끄러운 카드(이웃을 버림)를 제출하면 → 증언 신뢰도는 **오르지만** 개인적 대가 텍스트가 붙는다.

**학습 포인트**
> 증언은 선택된 기억이다. 사료는 남긴 사람의 것이다. 기록되지 않은 고통은 법정에 도달하지 못한다.

**결과값**: `testimonyScore`(신뢰도), `submitted[]`(제출한 3장), `withheld[]`(침묵한 3장) → 엔딩 카드로 전달.

### 4.2 문 ② 책임 — 누구의 죄인가 (2.5분)

법정에 네 개의 피고석이 있다. 학생이 **기소 우선순위를 매긴다**(클릭 순서 1→4).

| 피고 | 학생이 매긴 순위 뒤 제시되는 실제 역사 |
|---|---|
| **직접 사격한 병사** | 다수가 신원 미확인. ICTY는 하급 실행자보다 지휘부 기소에 집중했다 |
| **명령한 지휘관** | 라도반 카라지치·라트코 믈라디치 종신형. 스레브레니차에 대해 **제노사이드** 인정 |
| **개입을 미룬 국제사회** | 2019년 네덜란드 대법원, 스레브레니차 UN 네덜란드 대대의 **부분 책임** 인정(10%) |
| **이웃을 밀고한 시민** | 대부분 기소되지 않았다. 같은 도시에 그대로 살고 있다 |

각 항목에 실제 판결문·보고서 한 줄을 사료 카드로 붙인다. **정답은 없다.** 학생의 순위와 역사의 답을 나란히 보여줄 뿐이다.

**학습 포인트**
> 책임에는 층위가 있고, 법은 그중 일부만 다룬다. 처벌되지 않은 책임은 사라지는가?

**결과값**: `blameOrder[]` → 엔딩 카드 + 반 전체 집계.

### 4.3 문 ③ 이웃 — 함께 살 것인가 (2.5분)

> 옆집에 한 가족이 이사 왔다.
> 그 집 아버지는 포위 당시 언덕 위에 있었다.
> 그의 아들이 당신 아이와 같은 반이다.

| 선택 | 조건 | 뒤따르는 사료 |
|---|---|---|
| 말을 걸지 않는다 | 항상 | 보스니아의 '한 지붕 두 학교(Two Schools Under One Roof)' — 같은 건물에서 민족별로 분리 수업하는 학교가 아직 50여 곳 남아 있다 |
| 아이들만은 놀게 둔다 | 항상 | 전후 귀환 통계 — 실제로 고향에 돌아온 소수민족 주민은 등록 인원의 일부에 그쳤다 |
| 그 집 문을 두드린다 | `연대` 높으면 더 구체적 형태로 해금 | 스레브레니차 어머니회의 지속적 증언 활동, 그리고 여전히 존재하는 제노사이드 부인론 |

**학습 포인트**
> 과거사는 판결로 끝나지 않는다. 화해는 제도가 아니라 매일의 선택이다.

**결과값**: `neighborChoice` → 엔딩 카드.

```
┌───────────────────────────────────────────┐
│          나 의   기 록                    │
│   사라예보 · 1992  ─  2002                │
├───────────────────────────────────────────┤
│  버틴 날      12일   /  사라예보 1,425일  │
│  살아남은 사람  에미르, 야스나            │
│  잃은 사람      다보르 (9일차)            │
│  읽은 자료      12개 중 7개               │
├───────────────────────────────────────────┤
│  연대 ████████░░   기록 ██████░░░░        │
│  생존 █████████░   침묵 ███░░░░░░░        │

│   · 이웃의 이름을 수첩에 적었다           │

│  내가 매긴 책임    ① 지휘관 ② 국제사회    │

└───────────────────────────────────────────┘
```

### 5.1 토론 질문 (카드 하단 고정)

1. 당신이 **침묵한** 기억은, 왜 침묵했는가?
2. 처벌받지 않은 책임은 누구의 몫인가?
3. **우리 역사에서 아직 두드리지 않은 문은 무엇인가?**

3번은 동아시아사·한국 과거사(일본군 위안부, 강제동원, 한국전쟁 민간인 학살, 베트남전 한국군 문제)로 넘어가는 다리다. 교사가 이 질문 하나로 남은 수업 시간을 운영한다.

### 5.2 교사 운영 장치 — 6자리 기록 코드

카드 하단에 6자리 코드가 생성된다. 각 자리는 학생의 플레이를 인코딩한다.

| 자리 | 인코딩 대상 | 값 |
|---|---|---|
| 1 | 생존자 수 | 0–3 |
| 2 | 최고 태그 | Y(연대)/G(기록)/S(생존)/C(침묵) |
| 3 | 읽은 자료 수 | 0–9, A–C |
| 4 | 증언 신뢰도 | 1–5 |
| 5 | 책임 1순위 | 1(병사)/2(지휘관)/3(국제사회)/4(이웃) |
| 6 | 옆집 선택 | A/B/C |

학생이 패들렛·구글폼에 코드를 입력하면, 교사는 반 전체의 선택 분포를 즉석 집계해 토론 자료로 띄운다.

> "우리 반 28명 중 **19명**이 책임 1순위로 '지휘관'을 골랐습니다. '이웃'을 1순위로 고른 사람은 2명입니다. 왜 우리는 가까운 책임을 가볍게 볼까요?"

이 장치가 없으면 게임은 개인 경험으로 끝난다. 있으면 **반 전체의 선택이 그 자체로 토론 사료가 된다.**

## 6. 기술 설계

### 6.1 유지할 것

- **단일 HTML 파일** — 오프라인 배포, 크롬북·태블릿에서 파일 하나만 열면 됨. 학교 환경에서 검증된 방식
- 캔버스 2.5D 렌더러, 스프라이트 아틀라스, 눈·그레인·비네트 연출 — 몰입에 실제로 기여
- 코치 바(`#coach`) — 다음 할 일을 계속 지시. 20분 제약에서 필수
- 반응형 레이아웃

### 6.2 고칠 것

| 항목 | 조치 |
|---|---|
| 파일 크기 3.7MB | 배경·스프라이트 이미지 재인코딩(WebP 검토), 미사용 레닌그라드 자산 제거로 감축 |
| `localStorage` 키 | `shelterSave` → `sarajevo1425.v1`로 분리. **세션 시작 시 초기화** (공용 기기에서 앞 학생 저장 충돌 방지) |
| 이벤트 데이터 | `SCENARIOS.sarajevo.events` → 국면별 배열 `phases[0..2].events`로 재구성. 각 이벤트에 `source`(사료), `unlock`(해금 선택지), `tags` 필드 추가 |
| 선택 기록 | `S.learned[]`(제목+메모만 저장) → `S.choiceLog[]`로 교체. 각 항목 `{day, eventId, choiceId, tags, memoryCardText}` |
| 2막 상태 | `S.act2 = {submitted[], withheld[], blameOrder[], neighborChoice, testimonyScore}` 신설 |
| 레닌그라드 시나리오 | 제거 (사라예보 단독). 코드는 시나리오 구조를 남겨 향후 확장 가능하게 유지 |
| 랜덤 종료 | `CONFIG.truceMin/Max` 제거 → `CONFIG.totalDays = 12` 고정 |

### 6.3 새로 만들 것

| 모듈 | 역할 |
|---|---|
| `PhaseEngine` | 국면(1~3) 판정, 국면별 기온·위협·이벤트 풀 관리 |
| `SourceCard` | 이벤트 내 📄자료 UI, 읽음 처리, 선택지 해금 |
| `TagLedger` | 4태그 적립·조회. HUD 노출 금지 |
| `MemoryCards` | `choiceLog[]` → 기억 카드 6장 생성. 태그에 따라 물증/흐림 처리 |
| `Act2Scenes` | 문 ①②③ 순차 진행. 각 씬은 독립 모듈 |
| `RecordCard` | 엔딩 카드 렌더 + 6자리 코드 생성 |

**모듈 경계 원칙**: 1막(생존 시뮬)과 2막(과거사)은 `choiceLog[]`와 `TagLedger` **두 개의 인터페이스로만** 통신한다. 2막은 1막의 내부 상태(자원·방·스탯)를 직접 읽지 않는다. 이렇게 해야 각 막을 독립적으로 수정·테스트할 수 있고, 향후 다른 시나리오(레닌그라드, 한국전쟁)를 1막에 갈아 끼워도 2막이 그대로 작동한다.

### 6.4 검증 방법

브라우저 게임이라 자동화 테스트 비중은 낮다. 다음을 수동 시나리오로 확인한다.

1. **시간 검증** — 처음 보는 사람이 12일을 14분 안에 끝내는가. 교사 1회 + 학생 2~3명 사전 플레이로 측정. 초과 시 국면당 일수를 4→3으로 줄인다.
2. **태그 극단 케이스** — `침묵` 최대(모든 나눔 거절 + 자료 미독) / `연대`·`기록` 최대 두 가지로 완주해 2막이 정상 분기하는지 확인.
3. **전멸 케이스** — 3명 모두 사망 시에도 2막이 열려야 한다(생존자 시점이 아니라 유족·이웃 시점으로 전환). 이 분기 텍스트를 반드시 준비한다.
4. **공용 기기** — 연속 3회 플레이 시 앞 학생 데이터가 남지 않는지.
5. **코드 생성** — 서로 다른 플레이 5회가 서로 다른 코드를 내는지.

### 설계안에서 달라진 점

| 항목 | 설계안 | 구현 | 이유 |
|---|---|---|---|
| 방 축소 | 12칸 → 6칸 | **12칸 유지, 6종 행동** | 원본의 일러스트 단면도가 큰 자산이라 그림을 살렸다. 대신 각 방 우측 상단에 `식사·수면·치료·제작·야간 경계` 배지를 그려 무엇을 하는 방인지 즉시 알 수 있게 했다 |
| 자산 | 3.7MB 감축 | **624KB** | 원본 용량의 대부분은 미사용 레닌그라드 이벤트 이미지였다. 배경·스프라이트만 추출해 재사용 |
| 배낭 | 항상 6칸 선택 화면 | **넘칠 때만 선택 화면** | 후반에는 수확이 적어 고를 것이 없는데도 모달이 떠서 클릭만 낭비했다 |

### 플레이 테스트로 잡은 균형

초기 구현에서는 **자원이 6 → 29로 불어나** 후반에 압박이 사라졌다. 포위가 길어질수록 도시가 헐벗어야 하는데 반대로 풍족해졌다. 세 가지로 수정했다.

1. **도시 고갈** — 탐색 수확량에 국면 배수 적용 (1국면 ×1.0 → 2국면 ×0.7 → 3국면 ×0.45). **'희망의 터널'만 예외로 배수를 적용하지 않는다** — 바깥과 이어진 유일한 통로라는 역사적 사실이 그대로 메커닉이 된다. 후반에 살아남으려면 가장 위험한 곳으로 가야 한다.
2. **겨울 열량** — 2·3국면 허기 소모 26 → 34. 깊은 추위(-8℃ 이하)에는 난로가 연료를 2배로 먹는다.
3. **식량 공급 축소** — 시장·터널의 음식 산출을 낮추고, 빗물 수집기를 물 +2 → +3으로 올렸다. 물이 가장 먼저 마르는 자원이 되도록 했다.

수정 후 5회씩 자동 플레이한 결과:

| 플레이 수준 | 결과 |
|---|---|
| 유능 (난로·빗물받이 조기 건설, 사료 정독) | **3명 전원 생존**, 체력 8~86으로 소진, 음식 2~9 · 물 5 수준에서 종료 |
| 평범 (난로 늦게, 사료 안 읽음, 경계 없음) | **1~2명 생존**, 물 0 |
| 방치 (난로 없음, 시장만 반복) | **전멸** (11일차) |

의도한 곡선 — 초반은 견딜 만하고, 겨울에 조여들고, 후반에는 무엇을 포기할지 고르게 된다 — 이 나왔다.

1. **실제 소요 시간** — 자동 플레이로는 측정할 수 없다. 처음 보는 학생 2~3명으로 재어봐야 한다. 14분을 넘으면 국면당 4일 → 3일(총 9일)로 줄인다. `CONFIG.totalDays`와 `PHASES`의 `from`/`to`만 고치면 된다
2. **문 ③의 수위** — '가해자 이웃' 설정을 그대로 둘지 교사 판단
3. **6자리 코드 집계** — 실제로 쓸지. 쓰지 않으면 `makeCode()` 호출부와 `.codebox` 블록만 지우면 된다
