# 궁중 거점 구현 계획

**목표:** 역사 전환점을 유지하면서 9개 탐색 거점에서 방문 순서와 생략을 고르고 기록한다.
**설계:** `docs/superpowers/specs/2026-09-24-freedom-design.md`
**구조:** 독립 순수 규칙 모듈이 목록·비용·완료·마감을 관리하고 main.js가 기존 장면과 이동을 연결한다.
**도구:** 기존 ES 모듈·three.js·vitest·esbuild. 현재 워크트리에서 직접 순차 구현.

## 공통 제약

90비트 배열·저장 키·버전·조작권·역사 순서·사료 등급을 유지한다. 새 자산이나 의존성을 추가하지 않는다. 빌드는 13MB 미만. CODEX_TASK.md는 커밋하지 않는다.

## 작업과 시험

- [x] `src/systems/freedom.js`: 거점 찾기, 6개 보고·기록의 배치, 현재 시기의 방문 목록, 완료·미방문 기록. `tests/systems/freedom.test.js`에서 미래 보고 거부, 방 제한, 0칸 마감, 비용 단 한 번 지불과 기존 두 비트의 역순 열람을 시험한다.
- [x] `src/core/state.js`: 새 선택 기록 기본값 및 구형 버전 3 저장의 원래 좌표 보존. 같은 시험에서 보고 전·도중·뒤 저장과 구형 저장을 직렬화해 검사한다.
- [x] `src/ui/activity-board.js`, `src/systems/route.js`: 터치 가능한 선택 목록과 인물·보고 위치까지 걷기. 브라우저 시험에서 작은 화면의 버튼·닫기·마감, 경로 시험에서 실제 movement.step으로 도착을 검사한다.
- [x] `src/main.js`: 지정 보고를 거점에서 실행하고 같은 장면을 다시 강제 재생하지 않는다. 탐색 종료 시 기록, 마지막 사료 열람 중 종료 방지, 여정 판과 연결. 기존 나들이·E 대화도 기록으로 합친다.
- [x] `src/ui/act-end.js`: 방문 순서와 하지 않은 활동을 점수 없이 보여 주고 복사문에도 포함한다.
- [x] `tests/freedom-full-run.test.js`: 서로 다른 방문 순서, 모든 선택 생략, 1~5막 완주와 동일한 역사 이동, 모든 새 저장 경계에서 재개를 검증한다.
- [x] 구현 시험 통과 후 2단계 커밋. 전체 vitest 및 node build.mjs, 출력 크기와 제한을 검증 문서에 기록하고 3단계 커밋.

## 특히 확인할 입력

1. 해 칸 0과 마지막 사료 창: 닫기 전 다음 사건으로 넘어가지 않는다.
2. 보고 비용 지불 직후 새로고침: 재청구·카드 중복 없이 보고를 다시 보여 준다.
3. 구형 저장이 선택 보고를 이미 지나감: 보고를 다시 필수로 만들지 않는다.
4. 막/궁/조작권 변화: 이전 거점의 선택으로 다음 시대의 보고를 열지 못한다.
5. 인물과 출구가 같은 방에 있음: 명시적으로 고른 방문이 출구 행동에 가로채이지 않는다.
