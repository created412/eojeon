## 2. 가장 최근에 완성한 것

- 정책·문서 선택지와 낱말에 Higgsfield 그림 72장. 정책의 득실과 실제 역사를 단계별로 보여 준다.
- 큰 고딕 본문·투명 초상의 대화창. 대원군은 다른 실제 사진으로 교체했고 원본 확대 보기와 편집 고지를 보존했다.
- 안내와 막 종료 기록을 그림 중심으로 개편. 척화비 國의 얇은 윗획 안내점 누락 수정.
- 정족산성·광성보에 전장 그림과 병사·함선·연기·물보라. 정족산성은 성공해야 진행하고 광성보는 역사대로 함락된다.
- 머리 위 이름·목적·화살표 제거. 물 충돌과 다리 통행, 궁인 생활 동선, 두 궁에 궁녀 각 2명.
- 숨은 살림 물건 3종과 모음 보상, 사초함 재열람. 모두 재구성이며 필수 진행과 구분한다.
- 척화비·저장 복원·친정 직후 독백의 BGM 연결. 공통 소리 단추와 음소거·종료 정리.
- 오프닝 V23 즉시 재생 → 49~55초 영상 반복 → 오른쪽 아래 게임 시작. 별도 연속 음원은 영상 반복과 독립 진행한다. 마지막 화면 동결로 바꾸지 않는다.

궁녀는 Higgsfield 원화를 참고한 코드 입체 메시다. 3D 생성 도구로 만든 실제 GLB라고 설명하면 안 된다.

> (2026-10-06 밤, Claude Code) 위 문장은 옛말이 되었다 — 선생님의 「궁녀가 여전히 대충그린 그림이야」에 따라 Higgsfield image_to_3d(리깅)로 만든 실제 GLB(`assets/models/maid.glb` → `tools/pack-glb.mjs` → `MODELS.maid`)로 바꿨다. `render/palace-maid.js` 는 걷어 냈다.

## 3. 가장 중요한 최신 진행 규칙

사용자: 「사료 문제 틀릴때마다 그 막의 처음으로 돌아가게 만들어보자」.

사료 밑줄·따져 읽기·서계·문서 뜯어 읽기·저울의 확인 문항을 잘못 짚으면 **현재 막 도입으로 돌아간다**. 앞 막 기록은 보존한다. 정오가 없는 정책 판단과 회고는 제외한다. 예전의 「두 번이면 답이 빛난다」는 이 대상에 적용하지 않는다.

`src/systems/act-restart.js`가 막 시작 상태를 `actStart`에 깊은 복사로 보관하고 복원한다. 체크포인트 없는 구형 VERSION 7 저장에는 별도 복원 분기가 있다. 비트 좌표는 바뀌지 않아 이번에는 VERSION을 올리지 않았다. 이후 비트를 넣거나 빼면 저장 버전을 올려야 한다.

## 4. 이어받을 때 지킬 약속

- 사용자가 「올려」라고 하기 전에는 배포·push하지 않는다. 승인 대기 중 자동 배포나 배경 에이전트를 실행하지 않는다.
- `AGENTS.md`와 `_tools/`는 로컬 전용. 커밋하지 않는다. 저장소 루트에서 `git add -A`를 쓰지 않는다.
- 공개 GitHub에는 교과서 PDF 폴더 셋, `초기 원본 파일`, `명부.html`을 제외한다. 현재 브랜치 전체를 그대로 push하지 않는다.
- 다른 워크트리를 건드리거나 master에 병합하지 않는다. 로컬 커밋은 작업 단위로 해 왔다.
- 왕비를 게임에 넣지 않는다. 지문은 「당신」, 기록 속 인물은 「임금」. 글 입력칸·자동 걸어가기·납작한 인물 스프라이트를 되살리지 않는다.
- 학생 화면에 점수·정답·오답·실패·틀렸 같은 표현을 쓰지 않는다. 최신 막 재시작 규칙과 화면 표현 규칙은 함께 지킨다.
- 사료·해석·재구성을 구분한다. 실존 인물 얼굴과 사료 내용을 지어내지 않는다. 수치·인용은 근거를 읽고 확인한다.
- 새 그림은 사용자가 선호한 Higgsfield를 우선한다. 연결된 도구가 있는지 확인하고, 없는 도구를 썼다고 주장하지 않는다. API 키는 문서·소스·커밋에 남기지 않는다.
- 사용자 지시는 짧고 화면 중심이다. 기존에 승인된 범위는 불필요하게 되묻지 말고 작업 후 짧게 보고한다.

## 5. 실제 실행·전달 파일 — HTML만 넘기지 말 것

현재 `build.mjs`는 다음 세 파일을 만든다. 게임 본체 자산·BGM은 HTML에 내장되지만 오프닝은 동반 파일이다.

```text
dist/
  어전.html                                      16,181,832 bytes
  assets/video/eojeon-prologue-v23.mp4            25,586,417 bytes
  assets/video/eojeon-prologue-continuous.m4a      2,595,995 bytes
```

다른 PC에서 실행할 때는 `dist` 전체를 같은 구조로 전달한다. HTML만 전달하면 오프닝 파일 오류 안내에서 게임 시작은 가능하지만 정상 오프닝을 볼 수 없다. 루트 HTML은 루트 `assets/video/`를 상대 경로로 읽는다.

향후 배포 승인을 받으면 위 HTML을 `index.html`로 복사하고 `assets/video/` 두 파일도 함께 준비한다. **옛 AGENTS.md 9절의 HTML만 복사하는 배포 명령은 현재 파일 구성에 부족하다.** 원격 업로드 전에 파일 구성과 배포 서비스 제한을 다시 확인한다. 과거 공개본이 VERSION 6이라면 VERSION 7과 저장이 호환되지 않음을 알린다. 이번 인수인계는 배포 승인이 아니다.

## 6. 빌드·검사·화면 재현

PowerShell, 저장소 루트에서:

```powershell
node build.mjs
$env:EOJEON_TEST_EXISTING_BUILD = '1'
npx vitest run --fileParallelism=false
Remove-Item Env:EOJEON_TEST_EXISTING_BUILD
```

빌드가 성공했는지 확인한 뒤 검사를 실행한다. 기존 빌드 검사 환경변수는 새 코드를 자동 빌드하지 않으므로 소스를 수정한 뒤 빌드를 생략하면 안 된다.

실제 화면 점검은 설치된 Chrome과 Playwright로 한다. 로컬 `_tools/checks/gen2.mjs`로 저장 목록을 만든 뒤 `_tools/checks/ig.mjs <beatId>`로 장면을 열 수 있다. 76장면 검사 도구는 `_tools/checks/visual-overhaul-audit.mjs`다. 도구에는 이 PC 경로·런타임 경로 의존성이 있으므로 다른 PC로 옮기면 먼저 확인한다. 중복 ID `end`는 첫 막이 선택되므로 마지막 막은 `last-walk`에서 끝으로 진행한다.

## 8. 아직 확인하지 않은 것과 다음 시작점

실기기 Safari·태블릿, 실제 손가락 조작, 학생의 처음부터 끝까지 연속 완주, 수업 소요 시간·체감 난도는 미검증이다. 특히 현재 막 전체 재시작의 반복 부담은 수업에서 확인해야 한다. 76개 저장 진입 검사는 연속 완주를 뜻하지 않는다.

과거 AGENTS.md의 「프롤로그 넣기」「전장·궁녀 시각화」 등은 이미 끝난 일이 섞여 있으므로 남은 일 목록을 그대로 실행하지 않는다. `unyo-dispatch`, 급료 가마의 시각 구성, 학생 기록 내보내기, 안내서 전체 대조 등 과거 제안은 현행 화면과 후속 지시를 확인한 뒤 판단한다. 이번에는 새 기능을 주문받은 것이 아니다.

다음 작업자는 이 문서 → 로컬 AGENTS.md 상단 → 최신 통합 검증 기록을 읽고 `git status --short`와 `git log -3 --oneline`을 확인하면 된다. 사용자 후속 요청의 화면부터 현재 빌드로 재현하고 이어서 작업한다.
