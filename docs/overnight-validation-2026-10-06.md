# 어전 — 밤사이 추가 점검

2026-10-06. 사용자가 지적한 척화비 BGM 누락을 시작으로 음악·진행·저장 복원·조작을 추가 점검했다. 앞선 [Astra 6 검토](astra-quality-review-2026-10-05.md) 이후의 변경이며, 공개 배포·push는 하지 않았다.

## 수정한 문제

| 문제 | 수정 후 동작 |
|---|---|
| 척화비 붓쓰기가 예전 무음 목록에 남아 있었음 | 도입 글과 붓쓰기에서 Suno 연주곡을 낮게 반복 재생한다. 붓 효과음도 그대로 난다 |
| 보고·활동 뒤 탐색 복귀 시 막 번호를 넘기지 않아 1막 곡이 재생됨 | 현재 막의 곡으로 돌아온다. 2~5막도 각각의 음악을 유지한다 |
| 읽다 만 사료를 이어하면 음악 없이 기다림 | 현재 막의 읽기용 음량으로 음악을 재생하며 사료를 복원한다 |
| 막을 끝낸 저장에서 이어하면 마무리 질문이 무음 | 정상 진행과 복원 모두 현재 막의 낮은 음악으로 마무리한다 |
| 사료·회의·저울·막 질문에서 소리를 끌 조작이 없음 | 왼쪽 아래 「소리 켜짐/꺼짐」 단추를 추가했다. 현재 화면을 닫거나 진행을 바꾸지 않고 조절한다 |
| 음소거 뒤에도 BGM이 천천히 사라지고 짧은 종지 음악이 남음 | 음소거를 즉시 적용하고 재생 중인 종지·상실의 여음도 멈춘다. 소리를 다시 켜도 중단된 효과 음악을 되살리지 않는다 |
| 게임을 닫아도 이미 시작한 짧은 음악이 남을 수 있음 | 게임 종료 시 배경 음악과 짧은 음악을 모두 정리한다 |
| 척화비를 다 쓴 뒤에도 쓰기 안내가 결과 본문을 덮음 | 완료 시 쓰기 안내를 닫고 결과 화면 맨 위부터 보여 준다 |
| 스크롤한 본문이 고정 안내 띠 밑에 가려짐 | 본문을 내리면 안내 띠만 잠시 가린다. 여백은 유지하여 스크롤이 튀지 않는다. 맨 위로 돌아가거나 사초함을 닫으면 안내가 다시 보인다 |
| 멈춤 메뉴 위에 이전 장면 안내가 남음 | 멈춤 동안 안내를 가리고 재개 시 복원한다 |

오프닝의 49~55초 화면 반복과 별도 연속 음악은 유지한다. 사용자가 음소거하지 않는 한, 영상 반복 때문에 음악을 되감거나 끊지 않는다. 기록 상실·조작권 제한·혼자 있는 장면의 의도된 BGM 공백은 구별한다. 기록 상실 장면의 짧은 여음은 반복 BGM과 다른 일회성 효과다.

## 검증

- BGM 회귀 검사에서 척화비 연결·이미 시작한 종지의 음소거·게임 종료 정리를 먼저 실패로 재현한 뒤 수정했다.
- Chrome 자동 검사에서 척화비 실제 음원 디코딩·재생 시간 증가·일시정지 중 음악 연속·음소거·다시 켜기를 확인했다.
- Astra 6 재검토: 2막 탐색은 `act2 / 0.32`, 복원 사료는 `act2 / 0.17`, 1막 완료 저장은 `act1 / 0.17`로 실제 재생했다. 복원 사료를 밑줄 → 따져 읽기 → E로 마치면 비교 기록이 저장되고 대기 카드가 해제되며 탐색과 2막 음악으로 돌아왔다.
- **76개 저장 위치 음악 진입 검사 통과:** 실제 음원의 디코딩·재생 시간 증가·음량과 현재 장면의 곡을 대조했다. JavaScript 오류 0, 가로 넘침 0이며 공통 소리 단추도 클릭 가능한 위치에 있다. 거점으로 옮긴 보고 3개는 현재 러너 규칙에 따라 연결 장면으로 진입했다. [장면별 결과](qa/2026-10-06/audio-and-brush-report.json)
- **척화비 완료:** 1366×768과 844×390에서 실제 포인터 이벤트로 「主和賣國」 네 글자를 각각 도달률 100%로 완성했다. 결과의 오래된 쓰기 안내가 사라지고 첫 문장부터 표시된다. 붓을 놓으면 척화비 사료를 획득·읽음 처리하고 다음 비트 13을 저장하며 2막 음악으로 전환한다. 작은 가로 화면은 터치 가능 뷰포트에서 마우스 포인터를 자동 입력한 것으로, 실제 손가락 시험은 아니다.
- **안내 회귀 검사:** 스크롤 중 안내만 숨김·안여백 유지·맨 위 복원·멈춤 중 숨김·Q 사초함을 닫은 후 복원까지 실제 Chrome에서 통과했다.
- [Astra 6의 복원 음악·사료 읽기 재검토](qa/2026-10-06/astra-audio-restore-report.json)도 별도로 보관했다.

검사 도구 자체의 잘못도 구분했다. 첫 음악 검사에서는 일회성 `loss`를 반복 BGM으로 잘못 분류했고, 첫 붓 입력 도구는 현행 네 글자 대신 오래된 여덟 글자 주석을 따랐다. 조건을 현행 데이터에 맞춰 해당 검사들을 다시 실행했다. 최종 결과에는 그 재검증 증거를 반영했고, 최초 로그는 `_tools/checks/`에 남겼다. 네 글자·재시도 규칙과 맞지 않는 소스 주석 및 수업 안내도 정리했다.

최종 통합 검사: `EOJEON_TEST_EXISTING_BUILD=1 npx vitest run --fileParallelism=false` → **129파일·2,635개 모두 통과**, 152.65초. 전체 로그는 `_tools/checks/overnight-final-verified.log`에 있다. 새 게임 소리 단추의 사용자 클릭에서 오디오 잠금을 다시 풀 수 있도록, 예전의 「타이틀만 unlock 허용」 검사는 「프레임에서 unlock 금지·소리 단추 클릭에서만 허용」으로 갱신했다. 실제 클릭에 따른 재생·음소거는 별도의 Chrome 검사로 확인했다.

최종 빌드 `어전.html`과 `dist/어전.html`은 각각 **13,577,470바이트**로 동일하며 13 MiB 상한 이내다. SHA-256은 `13ccece1ccfc9dafb7ea653904811553ddb57cee7712baabe3870e3032747680`. 검사 전용 전역 변수는 빌드에 없다. 5막·76장면·저장 VERSION 7은 유지했다. [수정한 844×390 척화비 완료 화면](qa/2026-10-06/brush-finished-844.png)도 보관했다.

실제 음원 검사는 Windows Chrome의 HTMLAudio 디코딩·재생 상태·시간·음량을 계측한 것이다. 야간 자동 실행에서 PC 스피커 출력은 억제했다. 실제 태블릿·Safari의 음질·코덱 호환성, 학생의 체감 난도와 수업 완주 시간은 확인하지 않았다.
